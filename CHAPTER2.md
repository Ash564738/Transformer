CHAPTER 2. THEORETICAL BASIC AND RESEARCH METHOD
2.1. Theoretical Basis
Before describing how the system was built, this section reviews the main theoretical tools and methods that the study relies on: the traditional DGA diagnostic standards, the supervised machine learning algorithms, the weak-supervision labeling framework, the risk-scoring concept, and the software technologies used to deliver the results to end users.
2.1.1. Dissolved Gas Analysis and Traditional Diagnostic Methods
	Dissolved Gas Analysis (DGA) is based on the fact that, when the insulating oil and paper inside a transformer break down under thermal or electrical stress, they release small amounts of gases (H2, CH4, C2H2, C2H4, C2H6, CO, CO2) that dissolve in the oil. The relative amounts of these gases indicate both the type of fault (electrical discharge or thermal overheating) and its severity. Four traditional interpretation methods were reviewed and used as the theoretical basis for the labeling work in this study:
-	IEC 60599: an international standard that computes three gas ratios (C2H2/C2H4, CH4/H2, C2H4/C2H6) and compares them against published value ranges to classify the sample as PD, D1, D2, T1, T2, or T3.
-	Rogers Ratio: an earlier method that uses the same three ratios but reads them through the original Rogers lookup table. It is historically important and is the only one of the four with an explicit “Normal” class, though its table has gaps and cannot express some fault types.
-	Duval Triangle: a graphical method that converts CH4, C2H4, and C2H2 into percentages of their sum and plots the result as a point inside a triangle divided into fault zones.
-	Duval Pentagon: a newer graphical method that converts five gases (H2, CH4, C2H2, C2H4, C2H6) into percentages, computes a centroid point, and locates it inside a five-sided polygon divided into seven zones (PD/D1/D2/T1/T2/T3/S).
	In addition, IEEE C57.104 provides condition criteria based on Total Dissolved Combustible Gas (TDCG) and individual gas concentration limits, which complements the ratio-based and graphical methods above by giving an overall severity classification. These four ratio/graphical methods and the IEEE condition criteria together form the theoretical foundation for the labeling work.
2.1.2. Supervised Machine Learning Algorithms for Fault Classification	
	Once a labeled dataset is available, supervised machine learning can be used to learn the mapping from gas features to fault type directly from data, rather than relying only on fixed rules. Four widely used classification algorithms were used in this study:
-	Random Forest: an ensemble of decision trees, each trained on a random subset of the data and features (bagging), with the final prediction taken as a majority vote. It tends to be robust to noise and works well on small, tabular datasets such as DGA records.
-	XGBoost: a gradient-boosting algorithm that builds trees sequentially, with each new tree focused on correcting the errors of the previous ones. It generally achieves strong accuracy on structured/tabular data such as this one.
-	Support Vector Machine (SVM): a classifier that searches for the hyperplane that best separates the classes with the widest margin. With a non-linear kernel (RBF), it can capture curved decision boundaries between fault types.
-	Logistic Regression: a linear probabilistic classifier that estimates the probability of each class as a function of the input features. It is simple and interpretable, and is used here as a baseline against which the more complex models are compared.
	A key theoretical point behind the experiment design is the difference between in-domain accuracy (how well a model reproduces the labels it was trained on) and transfer/generalization ability (how well it performs on an independent dataset it has never seen). A model can score very highly on the first while performing poorly on the second, especially when the training labels were generated using a formula that overlaps with the input features - a situation known as circularity. This is why an external, field-confirmed reference set is used for evaluation rather than relying on internal accuracy alone.
2.1.3. Risk Scoring Concept
Although weighted expected-risk scores are common in asset management, this study does not introduce unsupported fault-severity weights. Severity is the IEEE C57.104-2019 rule-derived Status 1/2/3 condition class, and the fleet is ranked with a documented unweighted lexicographic evidence order. Current status is primary; concentration, delta, rate, trigger, qualitative fault context, and history are retained as separate evidence fields. This produces one comparable transformer-level priority row without claiming a failure probability.
2.1.4. Software Technologies for the Monitoring System
To make the research results usable in practice, the system also relies on standard web-application and natural-language-interface technologies. The monitoring dashboard follows a typical client-server architecture, with a backend service (Flask) responsible for data access and serving model predictions through an API, and a frontend application (Next.js) responsible for rendering interactive charts, tables, and screens for the end user. For natural-language search, the chatbot follows a Text2SQL / Retrieval-Augmented Generation (RAG) pattern: instead of retrieving passages from unstructured documents, a user question is turned into a structured, read-only database query, the query results are retrieved from the current dataset, and a language model turns those results back into a plain-language answer. This pattern keeps the chatbot's answers grounded in the actual data rather than in free-form generation, which is important for a diagnostic tool that engineers rely on
2.2. Research Method
This project employs a quantitative, data-driven research methodology centered on robust cross-dataset validation. By leveraging a large-scale industrial dataset (EGAT, Thailand) alongside an independent, inspection-confirmed reference dataset (IEC TC10), the study ensures that all analytical conclusions are grounded in empirical evidence rather than heuristic intuition. The overarching methodological principle guiding this research is to strictly decouple a model’s ability to replicate its training labels from its capacity to generalize to real, independently verified faults, prioritizing the latter in all evaluations. The research framework is structured into five core phases, which align with the implementation plan outlined in Section 5.
Data Acquisition and Traceable Preprocessing The foundation of the study relies on the raw EGAT dataset, comprising 4,563 records across 26 columns collected from 628 transformers between 2017 and 2024. To ensure data integrity, a traceable preprocessing pipeline removes duplicates, normalizes fields, corrects date order, imputes context fields only within defensible groups, and recomputes TDCG from measured combustible gases. Source values are retained in "_raw" columns before every transformation, while missing gas measurements remain missing rather than being fabricated.
Domain-Gap Diagnosis and Feature Engineering Initial baseline testing revealed that models trained directly on raw gas concentrations exhibited poor transferability to the independent IEC TC10 dataset (macro-F1 < 24%). To isolate and quantify the root causes of this distribution shift, an ablation analysis is conducted. Consequently, a refined set of 12 scale-invariant features—comprising specific gas ratios and percentage compositions—is engineered to mitigate the domain gap. The effectiveness of this feature transformation is validated through a class-conditional distribution comparison using the Kolmogorov-Smirnov statistic per fault class, providing a more reliable assessment than naive unconditional comparisons (Section 3.2.4).
Pseudo-Labeling via Traditional DGA Standards Due to the absence of inspection-confirmed ground truth in the EGAT dataset, traditional methods are treated as noisy labeling functions, never as ground truth. IEC 60599, Rogers Ratio, Doernenburg, Duval Triangle 1, and Duval Pentagon 1/2 are compared individually and in combinations by coverage, conflict, class distribution, and transfer performance. Snorkel estimates label-model probabilities without inserting arbitrary manual weights.
Predictive Modeling and Transfer Evaluation The modeling phase evaluates four supervised machine learning algorithms: Random Forest, XGBoost, Support Vector Machine (with an RBF kernel), and Logistic Regression. All models are trained on the unified 12-feature set using an 85% EGAT modeling split. To prevent data leakage, this split is strictly grouped by transformer identifier. Crucially, to avoid the circularity of in-domain accuracy—where models might simply memorize label-generating formulas—performance is evaluated based on zero-shot transferability to the IEC TC10 dataset, which contains 95 real-world, field-inspected fault cases. Evaluation metrics include macro-F1, strict accuracy, T1/T2-lenient accuracy, and per-class confusion matrices (Section 3.4).
Risk Assessment and System Integration Beyond offline analysis, severity is computed as the rule-derived IEEE C57.104-2019 Status 1/2/3 condition class. Fleet ranking is an unweighted lexicographic evidence order with current status first and concentration, rate, delta, trigger, fault-context tie-break, and history retained as separate evidence. This avoids unsupported severity weights while keeping one longitudinal summary per transformer. The system exposes these results through a Flask/Next.js dashboard and a read-only Text2SQL/RAG chatbot.
